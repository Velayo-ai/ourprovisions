Recipe view: the action block, by state

This replaces the full-width "✓ On This Week" pill, which looks like a button but doesn't say what tapping it does. Each state has three parts: a status line that can't be tapped, one main action that depends on where the meal is, and a quiet "Remove from This Week" link. Everything above and below the block (photo, title, ingredients, steps) is unchanged from slice (a).

Rules for the amendment

  1. Status is never a button. "✓ On This Week" is a small-caps line with no tap target and no pill shape.
  2. One main action per state, chosen by where the meal is. There are never two equal buttons side by side.
  3. Same words as the board: "Add to Shop", "This Week". Not "Shopping list" or "Plan".
  4. Same behaviour as the board: Add to Shop and Remove call exactly what the board's buttons and ⋯ → Remove call, with the same confirmation or undo. The meal always stays in the Library.
  5. Replay privacy (A5 / D2): each new button's accessible name comes from fixed copy or aria-labelledby. No meal name or count goes in any attribute. Allow-list changes are named in the spec.
  6. Share is about the recipe, not the plan, so it sits in the top bar beside Edit and stays the same in every state. It never competes with the main action. It's drawn as the box-with-up-arrow glyph: our own SVG, in the same line weight as the nav icons, inside a 44px tap target, with the fixed accessible name "Share" (replay-safe). (Outlined in the mockup: a reserved spot. It ships only when sharing a meal actually works. Never show a dead button.)
  7. After Remove, the sheet stays open and switches to state D. You're still looking at the recipe, and "+ Plan again" undoes the removal in one tap.
