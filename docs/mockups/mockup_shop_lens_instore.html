Design notes for the spec

  • Lens is a two-segment control — Aisles | A–Z, active segment filled. Both states visible at once, so nothing has to be decoded (a single button that named its destination read as the current state, which is the tri-state problem again). "Aisles" rather than "Categories" because once store ordering learns the layout, that's literally what the grouping becomes.
  • The tray is the only home for checked items in both views. No toggle, no descriptor line. Collapsed by default; expanded state persists for the trip. A checked item animates down into it so the person sees where it went.
  • Count copy changes from "4 of 12 checked" to "4 of 12 in cart" and flat's eyebrow becomes "8 to find" — the words the tray uses, so the vocabulary is one set.
  • Add button is a 56px floating + fixed to the viewport bottom-right, above the footer. It floats over the list and reserves no space: content scrolls beneath it, and only when the list is scrolled to its very end does the last row need a small clearance (one row-height of bottom padding) so the tray chevron isn't covered. It hides while the Wrap-up modal or Add sheet is open. No label — the sheet title "Add something" does the explaining on first tap.
  • "added here" tag on an in-store add is the visible face of the added_in_store event, for this trip only — it's not a permanent badge.
  • Store prompt appears once per session, only when no store is set; chips are the household's distinct store_name_raw values, most recent first. "Somewhere else…" opens a text field. Skip is honest — GPS still gets captured.
  • Mic (later): reuses the Galley mic button and listening state; the transcript fills the search box and runs the same add path. Multi-item utterances split on commas and "and" before anything smarter is considered.
